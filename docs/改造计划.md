> 方向决策（2026-07-10 确认）：做成**单人可维的"自动化 AI 情报产品"**，**不抄 B站式日更媒体 IP**。
> "企业级"重定义为**价值交付的可靠性**（每天自动跑、失败主动告警、内容可靠抵达用户），而非内部架构纯度。
> 原则：**本人体量优先**；增量式不重写；保住 61 项 pytest；大规模重构只允许落在"真实缺口"上。

## 0. 为什么是"重定义"而不是"大重构"

用户原话痛点："做到企业级，而不是连我自己都留不住的玩具"——这是**产品/留存**问题，不是工程问题。但增强版提示词把它翻译成了 6 条纯**工程内部质量**要求。实测代码（2026-07-10）后结论：**项目工程已非玩具级，6 条要求约 80% 已满足**。

| 用户"企业级"要求 | 代码现状（实测） | 判定 |
|---|---|---|
| ① 架构清晰/模块化 | `api/routes`·`api/services`·`api/models` 三层分离；`collector` 独立成类 | ✅ 已达标 |
| ② 健壮性（错误处理/日志/边界） | `arxiv/hf/rss_collector` 均含 retry/timeout/except；全局 logging；`daily_verify` 做数据完整性校验 | ⚠️ 基础在，边界校验可补 |
| ③ 安全（认证/授权/加密） | JWT(`jwt_verify`)+`admin_auth`+bcrypt 密码+auth 路由齐全；API 安全防护=JWT+admin 鉴权已做 | ✅ 已达标（静态加密/传输加密对本产品低价值） |
| ④ 可扩展性 | 服务化，新源=新 collector 子类 | ✅ 已达标 |
| ⑤ 可测试性 | **61 个 pytest** + 7 测试文件 + CI 门禁 | ✅ 已达标（远超多数 solo 项目） |
| ⑥ 部署运维 | 4 条 GitHub Actions(ci/daily/deploy/backup) + Supabase 自动部署；`daily.yml` 已含 `health_check` + `daily_verify` | ⚠️ **缺 Docker 化 + 流水线失败主动告警** |

**结论**：真正未做的工程只有两块——**Docker 容器化 + 流水线失败主动告警**。其余要么已达标、要么对本产品是过度工程（静态加密、横向扩展、微服务拆分、Grafana 级监控）。大规模重构内部架构对"留不住"这个真问题**贡献为零**。

**因此"企业级"重定义为**：
- **可靠性层（工程真缺口）**：Docker 化 + 失败主动告警 —— 让系统"挂了立刻知道、部署可复现"。
- **产品层（留存放 driver）**：社媒一手源(Agent-Reach) + 观点(So-What) + 分发(邮件简报) —— 让人"收到、且愿意留"。

## 1. 唯一真工程缺口：可靠性层（Phase R）

- **不做**：不把每日采集 cron 塞进容器（保持 CI 为单一真相源）；不引入 k8s（premature）。

### R.2 流水线失败主动告警
- `daily.yml` 新增 `notify-on-failure` job（`if: failure()`），复用现有 `scripts/feishu_notifier.py` 的 `FeishuNotifier.send_alert()`，把 GitHub **被动**失败通知升级为**飞书主动告警**（含 run 链接，已落地）。

- **不做**：不引入新监控平台（Grafana/Prometheus 属 premature）。

> 这两块就是用户那 6 条里**唯一值得做**的。做完即满足"企业级部署运维"的真实诉求，且不破坏任何现有能力。

## 8. 风险与对策
- **Agent-Reach 社媒渠道封号** → 专用小号 + Cookie；`doctor` 定时巡检；服务端走 `opencli`/MCP，**只读不自动发**。

- **邮件送达率** → 用正规 ESP（Resend 等），配退订与 SPF/DKIM。
- **Docker 镜像密钥泄露** → `.dockerignore` 排除 `.env`；运行时经 `env_file` 注入。
- **现有测试回归** → 每次改动跑 `pytest` + CI；加层不破层。
- **dogfood 流于形式** → 把"作者本人是日活"写进验收（1.5），不做则 P1 不算过关。
