# Signal — 产品内核

> 最后更新: 2026-07-03  
> 状态: 生效中（独立日报产品）

## 1. 一句话定位

**Signal 是 AI 行业日报聚合与阅读平台** —— 帮用户每天高效浏览、搜索、收藏 AI 资讯。

## 2. 核心用户路径（唯一主路径）

打开网站 → 看今日日报 → 点文章阅读 / 搜索 / 收藏 → 第二天再来看新日报

## 3. 必须有（P0）

- 多源自动采集（arXiv、RSS 等）
- AI 摘要、标签、重要性分级
- 日报生成与按日浏览
- 文章搜索、收藏、浏览历史
- 用户登录（Supabase Auth）

## 4. 文案规范（编辑部口吻）

全站使用固定「编辑部」口吻，不绑定真人，无"日更出镜"压力。

### 基本原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **署名** | 始终以"编辑部"自称，不暴露个人身份 | "编辑部的看法"、"编辑部认为" |
| **统一称呼** | 称产品为"Signal"或"Signal 每日情报"，不加前后缀 | 不写"我的 Signal"、"本宝宝" |
| **客观有观点** | So-What 观点层可以有立场，但不煽情、不标题党 | 不写"震惊"、"核弹级" |
| **谦逊可信** | 可用"暂未收录"、"信号待验证"承认边界 | 不假装无所不知 |
| **无真人痕迹** | 不用"小编"、"我"、"我们的小编" | 统一用"编辑部" |
| **风格一致** | 中文为主，专业术语保持英文原文 | "GPT-6" 不翻译为"生成式预训练转换器第六版" |

### 各场景口吻对照

| 场景 | 旧（免用） | 新（编辑部口吻） |
|------|-----------|----------------|
| 邮件简报标题 | "Signal 每日简报" | "Signal 每日 AI 情报简报" |
| 邮件正文落款 | "你收到此邮件，是因为订阅了..." | "你收到此邮件，是因为订阅了 Signal 每日 AI 情报简报。" |
| 公开页描述 | "公开归档页" | "Signal 每日 AI 情报简报 · 公开归档页。本页内容来自已公开的每日简报，可自由阅读、分享。" |
| 文章落款/作者 | （无） | 来源标注（不添加虚拟作者） |
| 404 / 错误页 | "Not found" / "文章不存在" | "未找到该页面" / "这篇文章暂时无法获取" |
| So-What 观点 | "这意味着..." | "对读者意味着" / "编辑部的看法是" |
| 邮件退订页 | "退订" | "退订 Signal 每日情报" |
| 系统提示词 | "请求过于频繁" | "请求过于频繁，请稍后重试"（保留原意，语气中性，不寒暄） |

### 关键禁止清单

- ❌ 不写"小编说"、"小编觉得"、"本宝宝"
- ❌ 不写"点个赞吧"、"转发给朋友"、"关注我们"
- ❌ 不写"我"、"我们的小编"、"大家好"
- ❌ 不写"今天这篇文章很有用"（应改为"本期值得关注"）
- ❌ 不在文章详情页添加虚拟作者头像/简介
- ✅ 可接受：邮件简报中"编辑部分析认为"、"编辑部注意到"

> 本规范适用于所有面向读者的输出：邮件简报、公开页、网站 UI 文案、系统提示语。后端报错/日志不受此约束。

## 5. 明确不做

- 不做文档上传、向量检索等非日报能力
- 不做多租户 SaaS（现阶段）
- 不做 Java 后端栈
- 不维护与其它产品的采集集成

## 6. 数据域

| 本仓库负责 | 说明 |
|------------|------|
| `articles`、`daily_reports` | 资讯与日报 |
| `bookmarks`、`reading_history` | 用户阅读行为 |
| `user_profiles`、`user_tags` | 用户画像与标签 |

Supabase 中若存在历史遗留表，**不由本仓库读写**。
